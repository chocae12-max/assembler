# 10장. Structures and Macros

## 1. 구조체(`STRUCT`)

관련된 여러 필드를 하나의 자료형으로 묶는다. 각 필드는 메모리에서 순서대로 배치되며 크기와 정렬에 따라 간격이 생길 수 있다.

```asm
COORD STRUCT
    X WORD ?
    Y WORD ?
COORD ENDS

point COORD <5, 10>
mov ax, point.X
```

`COORD <>`처럼 쓰면 정의한 기본 초기값을 사용한다. 구조체 배열은 원소 하나의 크기인 `TYPE`만큼 이동하면서 접근한다. 포인터로 접근할 때는 `(COORD PTR [esi]).X`처럼 자료형을 알려준다. 구조체 안에 구조체를 넣을 수도 있다.

위 예제의 `X`, `Y`는 각각 2바이트이므로 기본 배치에서는 `Y`가 시작 주소에서 2바이트 뒤에 있다. `OFFSET point.Y`로 해당 필드의 주소를 얻을 수 있다. `COORD 3 DUP(<0,0>)`은 좌표 세 개로 이루어진 배열을 만든다.

`ALIGN`은 필드나 변수를 적절한 주소 경계에 놓는다. 정렬을 위해 빈 바이트가 추가될 수 있으므로 전체 `SIZEOF`는 필드 크기를 단순히 더한 값과 다를 수 있다.

## 2. 공용체(`UNION`)

구조체는 필드가 각각 다른 자리를 차지하지만, 공용체의 필드들은 **같은 시작 주소를 공유**한다. 공용체 크기는 가장 큰 필드를 담을 만큼이다. 한 필드를 바꾸면 같은 메모리를 보는 다른 필드의 값도 달라진다. 동일한 비트들을 여러 형태로 해석할 때 쓴다.

## 3. 매크로(`MACRO`)

매크로는 자주 쓰는 명령어 묶음을 이름으로 정의한다. 호출할 때 실행 중에 별도 프로시저로 이동하는 것이 아니라 **조립할 때 명령어가 그 자리에 펼쳐진다**. 호출 오버헤드가 없지만 많이 사용하면 실행 파일의 코드 크기가 늘 수 있다.

```asm
mAdd MACRO target:REQ, value:REQ
    add target, value
ENDM

mAdd eax, 5
```

매개변수는 전달된 텍스트로 치환된다. `REQ`는 필수 인수다. 매크로 안에서 분기 레이블이 필요하면 `LOCAL`을 선언해 여러 번 펼쳐도 레이블 이름이 충돌하지 않게 한다.

매크로를 다른 매크로 안에서 호출하는 중첩도 가능하다. 정의를 별도 파일에 두었다면 `INCLUDE`로 가져온다. `.LST` 목록 파일이나 디스어셈블리에서 펼쳐진 명령어를 확인할 수 있다.

## 4. 조립 시점의 조건과 반복

- `IF`, `IFB`, `IFIDNI` 등은 조립 시점에 조건을 검사해 생성할 코드를 선택한다. 실행 중 조건을 검사하는 `.IF`와 구별한다.
- `EXITM`은 매크로 확장을 중단하며, 매크로 함수에서는 값을 돌려줄 때도 사용한다. `ECHO`는 조립 중 메시지를 출력한다.
- `REPEAT`, `WHILE`, `FOR`, `FORC`는 코드를 여러 번 **생성**한다. 프로그램 실행 중 반복하는 `LOOP`와는 다르다.
- 꺾쇠괄호 `<...>`는 텍스트 인수를 묶고, `%`는 표현식의 텍스트 확장, `!`는 특수문자를 문자 그대로 전달할 때 사용한다.

`IF`에는 레지스터나 실행 중 바뀌는 변수 대신 **상수식**을 넣어야 한다. `REPEAT 3`은 같은 명령어를 세 번 만들어 놓는 방식이며, `FOR`는 기호 목록, `FORC`는 문자열의 문자들을 차례로 순회하며 코드를 생성한다.

**빠르게 확인하기:** 구조체와 공용체의 메모리 배치, 매크로와 프로시저의 차이, 조립 시점과 실행 시점의 구분이 핵심이다.
