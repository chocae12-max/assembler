# 4장. Data Transfers, Addressing, and Arithmetic

## 1. 데이터 이동과 주소

- `MOV 목적지, 원본`: 원본 값을 목적지로 복사한다. 두 피연산자의 크기가 맞아야 하고, 메모리끼리는 한 번에 옮길 수 없어 레지스터를 거친다.
- `MOVZX`: 작은 크기의 **부호 없는 값**을 큰 레지스터로 옮기며 앞쪽을 0으로 채운다. `MOVSX`: 부호 비트를 복사해 **부호 있는 값**을 확장한다.
- `XCHG`: 두 값 교환. 메모리와 메모리 사이의 직접 교환은 안 된다. `LAHF`/`SAHF`는 플래그 일부와 `AH`를 주고받는다.
- `mov eax, var`는 변수에 **저장된 값**, `mov esi, OFFSET var`는 변수의 **주소**를 얻는다. `mov eax, [esi]`는 `ESI`가 가리키는 주소의 값을 읽는다.

예를 들어 `arrayW WORD 100h, 200h`에서 `mov ax, [arrayW+2]`의 결과는 `200h`다. `WORD` 하나가 2바이트이기 때문이다. `mov al, [arrayW+2]`처럼 읽는 크기를 바꾸면 일부 바이트만 가져온다.

## 2. 산술 명령어와 플래그

| 명령어 | 뜻 |
| --- | --- |
| `INC`, `DEC` | 1 증가·감소 (`CF`는 바꾸지 않음) |
| `ADD`, `SUB` | 덧셈·뺄셈 |
| `NEG` | 부호 반전, 즉 2의 보수 계산 |

계산 결과에 따라 `ZF`(0), `SF`(부호), `CF`(부호 없는 자리올림·빌림), `OF`(부호 있는 범위 초과) 등이 바뀐다. 예를 들어 8비트 부호 있는 값 `127+1`은 `OF=1`, `0-1`은 빌림이 생겨 `CF=1`이다. `PF`는 결과의 최하위 바이트에 1인 비트가 짝수 개일 때 설정된다.

`NEG`를 0이 아닌 값에 적용하면 `CF=1`이 된다. `AF`는 비트 3에서 비트 4로 넘어가는 자리올림·빌림을 나타낸다. 식 `Rval = -Xval + (Yval-Zval)`은 `MOV`로 값을 가져온 뒤 `NEG`, `SUB`, `ADD` 순서로 구현할 수 있다.

## 3. 데이터 크기와 주소 계산

- `OFFSET arr`: 배열 시작 주소. `TYPE arr`: 원소 하나의 바이트 수. `LENGTHOF arr`: 원소 수. `SIZEOF arr`: 전체 바이트 수.
- `arr DWORD 1,2,3`이면 `TYPE=4`, `LENGTHOF=3`, `SIZEOF=12`.
- `PTR`은 메모리 피연산자의 크기를 명시하거나 재해석한다. `LABEL`은 같은 메모리에 다른 자료형의 이름을 붙인다. `ALIGN`은 주소를 지정한 경계에 맞춘다.
- 간접 주소 지정 `[esi]`는 포인터가 가리키는 값을 읽는다. 다음 `DWORD` 원소는 `[esi+4]`처럼 원소 크기만큼 이동한다. `TYPEDEF`로 포인터 자료형을 정의할 수도 있다.

## 4. 반복문 예: DWORD 배열 합계

```asm
mov esi, OFFSET arr
mov ecx, LENGTHOF arr
mov eax, 0
L1:
    add eax, [esi]
    add esi, TYPE arr
    loop L1
```

`LOOP`는 `ECX`를 1 줄이고 0이 아니면 레이블로 돌아간다. `JMP`는 조건 없이 이동한다. 위 예제에서 합계는 `EAX`에 남는다.

문자열 복사도 `source[esi]`에서 한 글자를 읽고 `target[esi]`에 넣은 뒤 `ESI`를 증가시키는 방식으로 작성할 수 있다. 복사 횟수와 종료 문자 `0`까지 옮길지 확인한다.

**빠르게 확인하기:** 값과 주소(`var`/`OFFSET var`), 부호 확장(`MOVSX`/`MOVZX`), `CF`와 `OF`, 배열 원소 간격을 구별하면 된다.
