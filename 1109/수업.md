# 어셈블리 프로그래밍 2장 — x86 Processor Architecture

> 원본: `2. x86 Processor architecture-1.pdf` (44쪽)

## 1. CPU와 프로그램 실행

- 컴퓨터는 **CPU, 메모리, 입출력 장치**가 버스로 연결된 구조다. CPU 안에는 계산하는 **ALU**, 제어 장치, 레지스터, 클록 등이 있다.
- **레지스터**는 CPU 내부의 작은 저장 공간이다. 메모리보다 가까워 계산에 자주 쓰인다.
- 명령 실행 순서: **명령 인출(fetch) → 해독(decode) → 피연산자 가져오기 → 실행(execute) → 결과·상태 플래그 갱신**. 명령 포인터가 다음에 실행할 명령의 위치를 가리킨다.
- 메모리를 읽을 때는 주소 버스에 주소를 놓고 읽기 신호를 보낸 뒤, 데이터 버스로 돌아온 값을 받는다.
- 프로그램을 실행하면 운영체제가 파일을 찾아 메모리에 적재하고 프로세스를 시작·관리한다.

## 2. 32비트 x86 레지스터

| 레지스터 | 주로 하는 일 |
|---|---|
| `EAX` | 계산 결과, 함수의 반환값 |
| `EBX` | 일반 데이터 보관 |
| `ECX` | 반복 횟수 계산 |
| `EDX` | 연산·입출력에 사용 |
| `ESI`, `EDI` | 메모리·문자열 처리 시 원본과 목적지의 위치 |
| `ESP`, `EBP` | 스택의 맨 위, 스택 프레임 기준 위치 |
| `EIP` | 다음 명령의 위치 |
| `EFLAGS` | 연산 결과와 CPU 상태를 나타내는 플래그 |

`EAX`는 32비트이며 아래쪽 16비트가 `AX`다. `AX`는 다시 상위 8비트 `AH`, 하위 8비트 `AL`로 나뉜다. `EBX`·`ECX`·`EDX`도 비슷하게 나뉜다.

**자주 쓰는 상태 플래그:** `ZF`(결과가 0), `SF`(부호), `CF`(자리 올림/빌림), `OF`(부호 있는 연산의 범위 초과). 조건 분기에서 이 값들을 확인한다.

세그먼트 레지스터에는 코드 영역의 `CS`, 스택의 `SS`, 데이터 영역의 `DS` 등이 있다. `FS`, `GS`도 추가 세그먼트 레지스터다.

## 3. CPU 동작 모드와 x86-64

| 모드 | 수업 자료의 핵심 |
|---|---|
| Real-address | 옛 16비트 환경, 직접 메모리에 접근하는 방식 |
| Protected | 메모리 보호와 여러 프로그램의 실행 지원 |
| Virtual-8086 | 보호 모드 안에서 옛 실주소 프로그램 실행 지원 |
| x86-64의 64비트 모드 | 64비트 레지스터와 더 넓은 주소 공간 사용 |

64비트에서는 `RAX`처럼 `R`로 시작하는 레지스터를 쓰며 `R8`~`R15`가 추가된다. 예: **`RAX`(64비트) → `EAX`(32비트) → `AX`(16비트) → `AL`(8비트)**.

## 4. 메모리와 입출력

- **RAM**은 실행 중인 코드와 데이터를 두는 주기억장치이며, 캐시는 자주 쓰는 데이터를 더 빠르게 접근하도록 돕는다. 자료에는 DRAM, SRAM, ROM 등의 종류도 나온다.
- 입출력은 보통 **프로그램 → 운영체제 기능·라이브러리 → 드라이버 → 장치** 순서로 이뤄진다. 저수준 코드에서는 BIOS 기능이나 하드웨어 포트에 접근하는 방식도 소개한다.
- 도식의 핵심은 *CPU가 레지스터에서 계산하고, 버스를 거쳐 메모리·장치와 데이터를 주고받는다*는 것이다.
