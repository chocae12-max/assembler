# 어셈블리 프로그래밍 7장 — Integer Arithmetic

> 원본: `7. Integer Arithmetic.pdf` (65쪽)

## 1. 비트 이동과 회전

| 명령 | 핵심 동작 |
|---|---|
| `SHL` / `SAL` | 왼쪽으로 이동, 오른쪽 빈자리에 0 삽입 |
| `SHR` | 오른쪽으로 이동, 왼쪽 빈자리에 0 삽입 |
| `SAR` | 오른쪽으로 이동, 왼쪽에 기존 부호 비트 복사 |
| `ROL` / `ROR` | 밀려난 비트를 반대쪽 끝으로 돌림 |
| `RCL` / `RCR` | 캐리 플래그(CF)까지 포함해 회전 |
| `SHLD` / `SHRD` | 두 피연산자를 이용해 빈 비트를 원본의 비트로 채움 |

이동하며 밀려난 비트는 **CF**로 간다. 범위를 넘지 않는다면 왼쪽으로 1비트 이동은 **×2**, 오른쪽 논리 이동은 **÷2**처럼 활용할 수 있다. 음수의 부호를 유지하며 오른쪽으로 이동할 때는 `SAR`를 쓴다. 수업에는 비트 이동으로 여러 DWORD를 이동하거나 바이너리 숫자를 문자 `'0'`·`'1'`로 만드는 예제가 나온다.

## 2. 곱셈: MUL과 IMUL

- `MUL`은 **부호 없는 곱셈**, `IMUL`은 **부호 있는 곱셈**이다.
- 피연산자 하나인 형식은 곱해지는 값이 정해진 레지스터에 있다.

| 피연산자 크기 | 곱해지는 값 | 결과 저장 위치 |
|---|---|---|
| 8비트 | `AL` | `AX` |
| 16비트 | `AX` | `DX:AX` |
| 32비트 | `EAX` | `EDX:EAX` |

예: `mov al, 5` → `mov bl, 10h` → `mul bl`이면 **AX=0050h**다. 두·세 피연산자 `IMUL` 형식은 목적지 크기로 결과가 잘릴 수 있으므로 **OF/CF**를 확인한다.

## 3. 나눗셈: DIV와 IDIV

`DIV`는 **부호 없는 나눗셈**, `IDIV`는 **부호 있는 나눗셈**이다.

| 나누는 수의 크기 | 나눠지는 값 | 몫 | 나머지 |
|---|---|---|---|
| 8비트 | `AX` | `AL` | `AH` |
| 16비트 | `DX:AX` | `AX` | `DX` |
| 32비트 | `EDX:EAX` | `EAX` | `EDX` |

**부호 있는 나눗셈 전에는 나눠지는 값의 부호를 확장**한다: `CBW`(AL→AX), `CWD`(AX→DX:AX), `CDQ`(EAX→EDX:EAX). 예를 들어 음수 EAX를 32비트 수로 나눌 때는 `cdq` 후 `idiv`를 쓴다.

**0으로 나누거나 몫이 결과 레지스터에 담기지 않으면 예외가 발생**한다. 나누는 수를 먼저 검사한다. `DIV`/`IDIV` 후 산술 상태 플래그 값은 정의되지 않는다.

## 4. 큰 정수와 10진 보정

- `ADC`는 **원본 값과 CF를 함께 더한다**. 하위 자리에서 발생한 올림을 상위 자리 덧셈에 전달할 때 쓴다.
- `SBB`는 **원본 값과 CF(빌림)를 함께 뺀다**. 큰 정수를 여러 레지스터로 나눠 뺄 때 유용하다.
- 자료의 오래된 10진 보정 명령에는 `AAA`(비압축 10진 덧셈 뒤), `AAS`(뺄셈 뒤), `AAM`(곱셈 뒤), `AAD`(나눗셈 전), `DAA`·`DAS`(압축 BCD 덧셈·뺄셈 뒤)가 있다. **ASCII 문자 `'0'`의 코드는 30h**이므로 숫자값 0과 구분한다.
